# Build plan: ADR-0002 — STEP import pipeline (roadmap item 2)

> Generated by the `adr-plan` workflow (2026-07-24, run `wf_32b1c3d3-e7e`), 11 slices.
> Check slices off as they land; move this file to `doc/plans/completed/` when done.

## Phases (dependency-ordered, model-batched)

### 1. Mesh protocol seam — **fable** · verify
- [ ] `worker-mesh-protocol` — the `ImportedPart[]` / transferable envelope every other
      slice consumes. Sharp edges: transfer lists must name underlying ArrayBuffers
      (not views); positions/indices sharing a buffer transfer exactly once;
      occt-import-js output is views over the WASM heap that must be copied into fresh
      buffers before transfer. Silent failure modes (structured-clone fallback,
      detached buffers breaking only multi-part files) ⇒ adversarial verify pass.
      **Freeze this contract before phase 2 starts.**

### 2. WASM plumbing + protocol consumers — **opus batch**
- [ ] `occt-wasm-dependency` — add occt-import-js (ADR-0006 note: ADR-0002 is its
      required dependency ADR) + electron-vite WASM asset wiring. **Must be checked on
      a real packaged build (file:// paths), not just the dev server.**
- [ ] `step-import-worker` — Vite module-worker, lazy memoized occt init,
      ReadStepFile on received bytes (depends on the slice above)
- [ ] `three-geometry-and-bboxes` — BufferGeometry + per-part AABBs (parallel-safe)
- [ ] `mesh-volume` — signed-tetrahedron volume in `core/` · **verify**: closed-mesh
      detection must not falsely flag OCCT's duplicated-vertex tessellation as open

### 3. Assembly hierarchy extraction — **fable** · verify
- [ ] `assembly-part-extraction` — hierarchy traversal: 4×4 instance transform
      composition, duplicating meshes referenced by multiple instances, normals
      without translation, node-vs-mesh naming. Renders plausibly on flat assemblies
      and misplaces parts only on nested/instanced ones ⇒ adversarial verify, tested
      against a nested/instanced assembly.

### 4. UI pipeline, formats, guard rails — **opus batch**
- [ ] `drop-to-import-pipeline` — File→worker→store plumbing, status enum, busy state;
      owns the re-drop-while-parsing race. Land first in this batch.
- [ ] `stl-loader-path` — extension dispatch + STLLoader, normalize single unnamed
      non-indexed mesh into the ImportedPart shape
- [ ] `parse-failure-handling` — error variant in the worker message union, surfaced
      via DropZone's existing error display
- [ ] `import-timing-instrumentation` — parse timing + part/triangle counts (console)

### 5. Golden regression gate — **opus** · verify
- [ ] `golden-step-parse-test` — `samples/` STEP fixtures (simple part + assembly)
      with **hand-computed** expected volume/bbox/count. Verify pass guards against
      tautological goldens snapshotted from the pipeline's own output.
      Fixture sourcing can start early, in parallel (de-risks this gate).

## Critical path

`occt-wasm-dependency` → `step-import-worker` → `assembly-part-extraction` → `golden-step-parse-test`
